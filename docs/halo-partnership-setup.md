# HALO 기업 홈페이지와 제휴 접수

## 기존 구성과 변경 범위

- Vite, React Router, Tailwind 및 전역·편집 페이지 CSS를 사용합니다. Vercel이 정적 HTML·SPA 경로를 제공하고 `api/`의 Node 함수가 접수를 처리합니다.
- 기존 기업 홈은 활동 사진 슬라이더, HALO·KIRI 소개 및 스토어 링크, 이메일 제휴 문의, 회사 정보 푸터로 구성되어 있었습니다. 앱별 페이지, 초대, 데모데이, 기존 약관·개인정보 페이지, 사전예약 API와 체험단 참여 의향 필드는 보존했습니다. KIRI 소개는 현재 저장소의 공식 서비스 공개 상태를 따릅니다.
- 기존 Supabase 접근은 Vercel 서버에서 REST로 호출하는 방식입니다. 저장소에서 확인한 기존 SQL은 `kiri_preregistrations`이며, 기업 홈의 기존 이메일 문의에는 DB 쓰기가 없었습니다. 기존 관리자 프로젝트나 운영 스키마의 인증정보는 이 저장소에서 확인되지 않았습니다.
- 새 기업 홈에서 파트너 및 연혁의 공개 콘텐츠는 `src/data/companyData.js`의 검토된 항목을 사용합니다. 신규 DB 테이블은 차후 관리자 연동에 대비한 구조입니다. 사진은 기존 회사·끼리 에셋을 사용하고, 파트너 에셋은 `public/images/partners/`에서 교체합니다.
- 연혁 근거는 저장소 커밋 `0ce59d8`(HALO 출시), `657757a`(데모데이 활동 맥락), `06f30fc`(끼리 공식 공개)입니다. 데모데이 5위, 모두의창업 2차 1라운드 진출, 끼리 iOS/Android 출시는 팀 확인을 반영했습니다. MOU는 증빙과 공개 범위를 확인한 뒤 추가합니다. 한국관광공사 아쿠아필드 고양 소개 본문에서 시설 내 쉼스파를 확인할 수 있습니다. 시니허그 공식 웹사이트는 https://www.senihug.com/ 입니다.

## 운영 접수 활성화

### Supabase SQL Editor

1. **기존 프로젝트** SQL Editor에 `supabase/halo-partnership.sql` 전체를 붙여넣고 한 번 실행합니다. 동일 이름의 테이블이나 함수가 있으면 트랜잭션이 실패합니다. 기존 `kiri_preregistrations` 및 관리자 테이블·권한에는 변경을 적용하지 않습니다.
2. 접수 전에 DB 소유자 권한으로 만료 데이터 정리를 예약합니다. 기존 스케줄이 있으면 유지합니다. Supabase Cron을 사용하는 경우 아래는 SQL 적용 이후 실행할 별도 명령입니다.
   ```sql
   select cron.schedule('halo-partnership-purge', '*/5 * * * *',
     'select public.halo_purge_expired_partnership_data()');
   ```
3. 새 문의 테이블에서 Vercel의 `service_role` 직접 접근은 상태 조회용 `id` 컬럼에 한정됩니다. 저장은 RPC로 합니다. 별도 관리자 앱이 새 문의 본문을 읽거나 상태를 수정할 경우 관리자 인증 흐름을 확인한 뒤 해당 역할에 필요한 권한만 별도로 정의합니다.

### Vercel 운영 배포

1. 운영 배포 커밋 `91c4418`에는 제휴 함수가 없습니다. 기존 KIRI 상태 API는 같은 도메인에서 Supabase 연결을 확인했습니다. 루트의 `api/partnership-inquiry.js`와 `vercel.json`을 포함한 새 소스 커밋으로 운영 배포합니다. 이전 커밋을 재배포하면 API의 404가 계속됩니다.
2. 이미 연결된 Supabase URL과 서버 키는 그대로 사용합니다. 운영 도메인, 기본 고지 버전, 기존 KIRI 접수 제한 비밀값 또는 서버 키를 활용하는 기본값이 있습니다. 기존 문의 설정이 있으면 우선 사용합니다. 문의 보유기간은 승인된 값이 있어야 하며 `HALO_PARTNERSHIP_RETENTION_DAYS`가 없을 때 API는 503을 반환합니다.
3. 배포 후 `GET /api/partnership-inquiry`에서 `200`과 `ok: true`를 확인합니다. 승인된 테스트 연락 수단으로 전화번호만 포함한 문의 1건을 제출하고 `201`과 DB 행 1건을 확인합니다. 동일 요청 ID를 재전송하면 `200`과 행 1건이 유지됩니다.

서버는 공개 입력을 검증하고, Vercel이 제공하는 IP 헤더, 서버 비밀값으로 만든 HMAC, 동시성 제어가 적용된 Supabase RPC로 접수 빈도를 제한합니다. 제출 API의 직접 테이블 쓰기 권한은 없으며, 접수와 제한 기록은 한 DB 트랜잭션에 저장합니다. 운영 DB 접속 및 정책 설정이 없으면 이메일 문의를 안내합니다.

## 후속 연동

- 파트너 로고와 갤러리는 사용 승인 기록이 확보된 파일만 등록합니다. 쉼스파의 공식 링크와 각 기업의 협력 상태도 운영팀 확인이 필요합니다.
- 첨부자료는 현재 접수 후 담당자가 요청해 전달받습니다. 운영 Storage의 버킷 및 정책을 확인한 뒤 기업·상품 소개서와 제안서를 PDF 등 승인된 형식과 크기로 제한하고, 비공개 버킷, 서버 검증, 권한 확인 후 서명 URL 발급, 테이블과 일치하는 보유기간을 적용해 연결하는 작업이 남아 있습니다.
- 공개 프로그램 및 신청은 실제 합의와 접수 승인 후 활성화합니다. 관리자 프로젝트가 확인되면 기존 관리자 인증 및 권한 구조를 검토해 공개 컨텐츠와 문의·프로그램 모델을 연결합니다.

## 간편 문의 데이터

초기 문의는 한 화면에서 기업명, 담당자 이름, 전화번호 또는 이메일 중 하나, 협업 유형, 개인정보 동의를 받습니다. 제안 내용과 홈페이지·SNS는 선택입니다. 새 개인정보 고지를 배포할 때 승인된 `HALO_PARTNERSHIP_POLICY_VERSION`을 갱신합니다.

간편 문의는 최초 마이그레이션의 `details` JSONB와 저장 RPC를 사용합니다. 기존 프로젝트의 다른 데이터에는 쓰지 않습니다. RPC의 기존 `email_key` 인자는 이메일 우선의 연락 수단 HMAC을 전달받습니다. 전화번호만 제출되면 숫자만 추출해 별도의 전화번호 네임스페이스로 변환합니다. 문의와 빈도 제한 기록을 처리하는 기존 권한과 만료 규칙을 적용합니다.
